# 手元の家計簿

ChatGPTとGmailでカード利用通知・銀行残高のスクショを読み取り、端末のIndexedDBに家計簿を保存する個人用アプリです。金額の計算、承認、残高の照合はJavaScriptが行います。ビューワはGitHub Pagesに配置でき、初回読込後はオフラインで使えます。

この配布版にはビューワ、中継用Cloudflare Worker、テスト、公開手順を含みます。公開先リポジトリと中継URLは未設定です。実際の利用通知・口座残高は含みません。

## できること

- 入力候補の確認・訂正・承認・却下。承認済み記録への訂正案は、承認するまで確定集計に反映しません。
- 月別の確定支出、返金、収入、費目別支出、口座・財布・カードの残高計算。
- クレジットカード利用は支出、銀行からカードへの引落しは振替として処理し、支出を二重計上しません。デビットカード利用は銀行口座の支出として入力します。
- スクショまたは申告の実残高を仮登録し、承認後に計算上の残高と比較。差額の修正案を別途承認できます。
- 暗号化バックアップの保存・復元、中継への同期、ChatGPT分析用データの出力。
- 同じ通知の再取得を抑止。元メールID、候補ID、修正・承認履歴を保持します。

## まず試す

PCでNode.js 24以降を使います。通常のローカル実行と単体テストは外部パッケージ不要です。

```sh
cd local-ledger
npm test
npm run dev
```

ブラウザで `http://127.0.0.1:8787/` を開きます。Androidでの日常利用には、後述のHTTPS公開先を使います。HTMLファイルを直接開く方法ではService Workerが動作しません。

1. 「設定・バックアップ」で口座の呼び名、基準日、基準残高を入力します。基準日は**その日の開始時点**です。カードの未払い分はマイナスで入力します。未入力の残高は「未設定」です。
2. 「記録・承認」で取引を追加し、確認して承認します。
3. 「残高の照合」で実残高を登録・承認します。明細を確認してから、必要な修正案を承認します。
4. 「暗号化バックアップ」で12文字以上の復元用パスフレーズを設定し、別の場所に保管します。

中継が未設定でも、手動入力・集計・承認・バックアップ保存は使えます。`examples/drafts.json` は架空の確認待ちデータです。「記録・承認」のファイル取込で試せます。

## 毎月10日・26日の照合

日本時間で毎月10日・26日に確認します。銀行の実際の反映日は銀行明細で確認してください。

引落処理後の残高スクショを、件名 **「家計簿 残高照合」** で自分のGmail宛てに送ります。本文に、アプリで使う口座の呼び名、撮影日時、引落しの反映を明細で確認したかを書いてください。残高しか写っていない画像では引落完了を推測しません。複数口座は画像と呼び名を対応させます。

ChatGPTが画像を読み、中継へ実残高の候補を送ります。ビューワを開いて同期すると、照合候補が届きます。画像の金額・時点・口座を確認して承認し、記帳漏れなどを訂正します。原因が不明な差額は費目を推測せず、残高調整の候補にします。

照合は**日付単位**です。同日の撮影後に入出金がある場合は明細も確認してください。基準残高が未設定の場合は差額を計算できません。

この会話では10日・26日、日本時間19時ごろのスクショ確認タスクを設定済みです。中継への自動入力は、公開・ChatGPT接続後に `docs/chatgpt-workflow.md` の指示へ更新します。

## 保存とバックアップ

家計簿本体は利用ブラウザのIndexedDBです。チャット履歴を台帳にしません。中継に置くのは口座の呼び名・種類、未取込の入力候補、暗号化バックアップです。口座番号、メール全文、画像自体は中継に送りません。入力候補は端末の保存完了後に中継の内容を消去し、重複防止用の識別情報だけ残します。

バックアップはAES-256-GCMで暗号化し、PBKDF2-SHA256で鍵を導出します。復元用パスフレーズは中継・メール・家計簿JSONに含めません。中継には最新10版を保存します。メール添付は**最後に端末から同期した版**です。端末が閉じている間の未同期編集はメールに入りません。

IndexedDBは端末・ブラウザ・公開元の組合せで別の保存領域になります。シークレットモードは使わず、Androidの同じブラウザを主端末として使ってください。URL変更や端末変更の前にバックアップを保存します。ブラウザのデータ削除後はバックアップから復元します。「端末への保存を保護する」はブラウザに継続保存を求めますが、利用者によるデータ削除を防ぐ機能ではありません。

この版は複数端末の同時編集を統合しません。中継は古い版や同じ版番号の異なる内容を拒否します。主端末以外で使う場合は最新バックアップを復元し、元の端末での編集を止めてから切り替えてください。

## 公開と連携

詳細は [公開手順](docs/deploy.md) と [ChatGPTの運用指示](docs/chatgpt-workflow.md) にあります。

1. 専用GitHubリポジトリへコードを配置し、GitHub Pagesの公開元をGitHub Actionsに設定。
2. Cloudflare WorkerとD1を公開し、独立した接続キー・認証パスワードを設定。
3. ビューワで中継URL・接続キー・暗号化を設定し、初回同期。
4. ChatGPTに中継のMCPを接続し、Gmailと併用。カードの対応関係を指定。
5. カード通知の定期取得、10日・26日の照合、週次メールバックアップを設定。

GitHub Pagesにはプログラムだけを公開します。実データ、接続キー、パスフレーズ、スクショをコミットしないでください。中継は1人用です。複数ユーザー向けの認証・権限分離は実装していません。

## 検証

`npm test` は計算、訂正前の確定値維持、照合、再取得の重複、暗号化・復元・改ざん検知、OAuth認証、入力待ち処理、バックアップの競合防止、Gmail添付形式を検証します。

`node tests/http-smoke.mjs` は一時DBと確認用サーバーで、GitHub Pages相当のサブパス配信と実際のHTTP経由の認証・候補送信・取得を確認します。

ブラウザでの一連の確認には、開発用のPlaywrightを追加します。上のローカルサーバーを起動したまま、別ターミナルで実行してください。**新しいテスト用のローカルDB**を使います。

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/browser-smoke.mjs
```

GitHub Pagesのサブパスを試す場合は、サーバーを `DEV_MOUNT=/book/ npm run dev` で起動し、`LEDGER_TEST_URL=http://127.0.0.1:8787/book/ node tests/browser-smoke.mjs` を実行します。

## 構成

| 場所 | 内容 |
| --- | --- |
| `web/` | GitHub Pages用の静的ビューワ、IndexedDB、計算、暗号化、オフライン処理 |
| `relay/` | Cloudflare Worker、MCP、OAuth、D1のスキーマ |
| `scripts/` | Node.jsのローカル確認サーバーとSQLiteのD1互換ラッパー |
| `tests/` | 自動テストとブラウザ確認スクリプト |
| `docs/` | 公開手順、ChatGPTの運用指示、今回の検証結果 |
| `examples/` | 架空の入力候補 |

OpenAI APIキーは使いません。ChatGPTとGmailの接続を利用します。
